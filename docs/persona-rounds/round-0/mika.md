## What worked

- The class contract is the best thing here. `skeleton/CLASS-CONTRACT.md` is complete enough that I wrote Ledger (~200 lines, two-column grid on screen, Letter `@page` in print, old-style figures, small-caps labels) in one sitting without touching a line of HTML. §6's "complete selector surface" and "No other `rz-*` classes exist in HTML contract 1.0" is exactly the promise a CSS Zen Garden needs.
- The skeleton is honest markup: one `h1`, `h2` sections, `h3` entries, `<address>`, `<nav aria-label="Profiles">`, `<time datetime>`, real `mailto:`/`tel:` links. `.rz-entry-header` as a self-contained cluster makes `grid-template-areas` trivial. Modifier classes (`.rz-is-current`, `.rz-date--present`, `.rz-section--{id}`) are consistent throughout.
- "One `.css` file, `/* rz-target: both */` in a comment, no JS" is real. No build, no signup, no framework to write a theme. The rules in §2 (motion off in print, honor `prefers-reduced-motion`, words stay in HTML) are the rules I would have written.
- The switcher swaps themes with no unstyled flash (dual-link swap in `ports.js`), `?theme=quarto` is a shareable permalink and Back works — that's the URL I'd put in a portfolio once I'm in.
- Print actually prints the theme: the Print button calls `iframe.contentWindow.print()` (verified: 1 call in the child, 0 in the shell), and Ctrl+P on the shell hoists the résumé so it paginates identically (3 pages for Quarto both ways). Nothing broke in the print dialog.
- Quarto's screen proof is genuinely lovely type. Small caps, oxblood rules, Garamond. No horizontal overflow or clipped dates at 1280px (the QA bar's BAR-U2 note is stale on this build).
- Light/dark chrome and the 390px layout of the Garden itself are clean; the sandbox iframe keeps my CSS out of the UI as promised.
