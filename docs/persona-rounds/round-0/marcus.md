## What worked

- The renderer is correct on the things JSON Resume themes usually get wrong. My file has all twelve body sections and all twelve came out, in schema order: `SECTIONS: ["summary","experience","volunteer","education","awards","certificates","publications","skills","languages","interests","references","projects"]`. Certificates with and without URLs, publications, references, languages, interests-with-keywords (`data-rz-kind="entries"`), project `roles`/`entity`/`type` as `.rz-meta` — all present.
- Escaping is right. `<observability>` and `<angle brackets> &` in my text came out as text, not markup. The 150-character LinkedIn URL with four `&` query params is `&amp;`-escaped in `href` and round-trips byte-exact.
- Long URLs do not break layout. `overflow-wrap: anywhere` in all three themes; the page never overflowed horizontally at 1280px (`docScrollWidth 1280 == docClientWidth 1280`), and the GitHub URL in a bullet wraps cleanly in print.
- Privacy defaults are the right way round: `basics.location.address` and `postalCode` are not rendered (verified: "Guerrero" and "94110" absent from output); `meta.x-marcus-private-note` never appears. Contact hrefs are real: `mailto:marcus+resume@...`, `tel:+14155550199`, `https://okafor-lindqvist.dev` (scheme added to my bare hostname).
- `null` in optional fields (`"label": null`, `"endDate": null`, `"highlights": null`, `"certificates": null`) is tolerated. Truly invalid input (an array inside `highlights`) fails with a precise position: `invalid type: sequence, expected a string at line 10 column 8`. When paste exists, surface that string verbatim.
- Entry slugs and current-state are sane: `data-rz-entry="halyard-systems-2021"`, `data-rz-current="true"` on my current job and my maintained project; `<time datetime="2018-03-12">` carries the raw ISO value with a locale-formatted label.
- The theme switcher is genuinely a stylesheet swap (`#theme-stylesheet` href inside the iframe), `?theme=quarto` is a working permalink, and the Print button prints the child document so the theme's `@page` wins (Quarto letter, Switchyard A4, verified by `pdfinfo`). Print preview toggles `@media print` rules in-page. That architecture is the part that could beat GitHub Pages: one HTML, live restyle, real print CSS. It just is not attached to my data yet.
- The repo says the right things about ownership: README "JSON Resume as the only stored/pasted data shape", CONTEXT.md "Never the stored form" for bridge dialects, contract §1.8 "Unknown `additionalProperties` are preserved in storage". No walk-away.
