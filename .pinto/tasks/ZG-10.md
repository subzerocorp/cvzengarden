## Why
Mika had to render real PDFs to learn Quarto was 3 pages and Elena did not know "Save as PDF" lives in the print dialog; a page estimate and one hint close that gap without a PDF pipeline (Mika, Elena, Priya).
## Covers
E4 — Mika, Elena
## Scope in
- In Print preview, a readout `[data-page-estimate]` "About N pages (Letter|A4)" computed in `ports.js` from the print-emulated document height and the theme's `@page size` (parsed from the loaded sheet's `CSSPageRule`, default Letter) minus margins; recomputed on theme switch and after a paste
- Hint under the print button: "Choose "Save as PDF" in the print dialog to get a PDF."
- Page-boundary guide lines drawn by the chrome **outside** the iframe content (an overlay in `.garden-stage--print`), not injected into the Skeleton
## Scope out
- True paginated sheets — browsers do not expose paged-media layout; a paged-media polyfill (e.g. paged.js) is a third-party runtime and is not this round
- A server PDF pipeline (Phase 5)
- Exact fidelity: the readout says "About"
## Acceptance criteria
- [ ] Probe `ZG-10/estimate-matches-pdf`: for each first-party theme on `skeleton/resume.json`, `[data-page-estimate]` N equals the page count of Playwright `page.pdf()` for the same theme (existing `countPdfPages`) ± 0 for Quarto and Switchyard, ± 1 for Nightgarden
- [ ] Probe `ZG-10/paper-size`: the readout says `Letter` for Quarto and Nightgarden and `A4` for Switchyard (from their `@page` rules)
- [ ] Probe `ZG-10/updates`: after pasting `frontend/fixtures/long-resume.json` (created in ZG-11; if absent, a 4-job fixture created here) the estimate increases; switching to Screen hides the readout
- [ ] Probe `ZG-10/hint`: text `Save as PDF` is visible next to the print button in both views
- [ ] Probe `ZG-10/no-skeleton-injection`: the iframe document contains no element that is not part of the rendered Skeleton or the theme `<link>` (no overlay nodes inside the sandbox)
- [ ] `just verify` green
