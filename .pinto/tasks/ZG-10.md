## Scope in
- Pure module `frontend/static/page-estimate.js` (ES module, no DOM, imported by `ports.js` and by a node unit test): `pageGeometry(pageRules)` → `{ paper: "Letter" | "A4", source: "declared" | "default" | "fallback", contentWidthPx, contentHeightPx }`; `estimatePages(heightPx, contentHeightPx)` = `max(1, ceil(heightPx / contentHeightPx))`; `estimateLabel(n, paper)` = `About 1 page (Letter)` / `About 3 pages (A4)` (singular at 1)
- `pageRules` is the list `ports.js` collects from the loaded theme sheet (`collectPageRules(sheet)`): every `CSSPageRule` (`rule.type === CSSRule.PAGE_RULE`) in sheet order, recursing through `CSSMediaRule` / `CSSSupportsRule` `cssRules` (Nightgarden's and Switchyard's `@page` sit inside `@media print`; Quarto's is top-level), as `{ selector: rule.selectorText, size: rule.style.getPropertyValue("size"), marginTop, marginRight, marginBottom, marginLeft }` (longhands via `getPropertyValue`)
- Geometry rules: only base rules (`selector === ""`) count — `:first`, `:left`, `:right` and named pages are ignored (Quarto's `@page :first` returns `size: ""` and must not shadow the base rule); the last base rule wins; `size` is trimmed and compared case-insensitively (CSSOM returns lower-case `a4`): `letter` → 816 × 1056 px, `a4` → 793.7 × 1122.5 px (96 dpi); no base rule or empty `size` → Letter with `source: "default"`; any other value (`8.5in 11in`, `a4 landscape`, `legal`) → Letter with `source: "fallback"`, never a throw. Margins in `in` / `cm` / `mm` / `pt` / `px` convert at 96 dpi; a base rule with no margins assumes 1 cm each side (Chromium's print default). `contentWidthPx` = paper width − left − right; `contentHeightPx` = paper height − top − bottom. Today: Nightgarden 720 × 994.56, Quarto 681.6 × 945.6, Switchyard 672.8 × 1009.1
- Height `H`: in Print preview (ports.js `emulatePrint` active), `ports.js` sets the iframe `documentElement.style.width` to `contentWidthPx`, reads `.rz-resume.getBoundingClientRect().height`, and removes the inline width — synchronously in one task, so the constrained layout never paints and the iframe `html` carries no inline style afterwards. The preview column is wider than paper and would under-read
- Recompute on: theme swap settled (end of `setThemeHref`), View toggled to Print preview, and a `ResizeObserver` on the iframe `body` (a ZG-5 paste swaps `article.rz-resume`, fonts load, the viewport changes) — coalesced to one computation per animation frame; result sent to Elm through an inbound port `pageEstimate`
- Readout rendered by Elm only in Print preview: `<p class="preview-controls__pages" data-page-estimate="N" data-page-size="Letter|A4" data-page-size-source="declared|default|fallback">About N page(s) (Paper)</p>`; absent from the DOM in Screen view
- Hint in both views, in its own element under the print button and after ZG-7's sentence "What you see here is what the printer prints.": `<p class="preview-controls__hint" data-pdf-hint>Choose "Save as PDF" in the print dialog to get a PDF.</p>`
## Scope out
- Page-boundary guide lines (an overlay at multiples of page height) — the preview is one unpaginated column, so an overlay cannot reflect where `break-inside: avoid` actually pushes content; a line that says "the page breaks here" when it does not misleads exactly the print Designer (Mika, E1) this item serves. The readout can honestly say "About"; a guide line cannot
- Modelling `break-before: page` / `break-inside: avoid` in the estimate — the same reason: a column height cannot see them, so the readout is exact against the stated formula and only ± 1 against a real PDF (Switchyard today: formula 2, PDF 3 because of its forced break before Projects). Exact-vs-PDF is not claimed
- `@page :first` margins — an "About" estimate ignores them; ZG-11's `printableHeightPx` page-1 helper serves a different oracle and is not reused (no ZG-11 dependency)
- A paste route in the probes — recompute after a content change is proven with a probe-side DOM edit, so ZG-5 is not a dependency and no long fixture is needed (ZG-11 owns `frontend/fixtures/long-resume.*`; unused here)
- True paginated sheets — browsers do not expose paged-media layout; a paged-media polyfill (e.g. paged.js) is a third-party runtime and is not this round
- A server PDF pipeline (Phase 5)
