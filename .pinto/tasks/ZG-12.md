## Why
"Okafor-Lindqvist" paints past Nightgarden's rail, sections below Experience are invisible to crawlers and Cmd-A until scrolled, and a highlight with embedded sub-bullets collapses to one run-on line in every theme (Marcus, Mika).
## Covers
E3 (name overflow, `rz-rise`), D5 (highlight newline) — Marcus, Mika
## Scope in
- `themes/nightgarden.css` `.rz-name`: `overflow-wrap: anywhere; hyphens: auto;` and a container-query or `clamp` step that fits ≥ 24-character names inside `.rz-identity`
- `rz-rise` today: `@keyframes rz-rise { from { opacity: 0; transform: translateY(1.15rem) } }` at top level, `.rz-section { animation: rz-rise 0.7s … both }` at top level (line 225), and `@supports (animation-timeline: view())` only swapping the timeline to `view()` with `animation-range: entry 0% entry 32%` — so in Chromium every below-fold section sits at `opacity: 0` (fill `both` applies the `from` keyframe before the range) until it enters the scrollport, and in a browser without scroll-driven animations it plays a time-based entrance. After this PBI: the `.rz-section` animation (`animation-name: rz-rise`, its timing, `animation-timeline: view()`, `animation-range: entry 0% entry 32%`) is declared **only** inside `@supports (animation-timeline: view())`, with `animation-fill-mode: forwards` (never `both`/`backwards`), so that before a section enters the scrollport it sits at its natural, fully painted style (`opacity: 1`, no transform) and the fade-in only plays while its top edge crosses into view — visually the same rise for a human, painted for Cmd-A, crawlers and screenshots; the `.rz-section:nth-of-type(n) { animation-delay }` rules move inside the block or are removed. Outside that block `.rz-section` has no `animation` at all and computes `opacity: 1`; the `@media print, (prefers-reduced-motion: reduce)` guard stays
- Nightgarden's two other animations stay untouched: `.rz-name { animation: rz-name-sheen 3.6s ease-in-out infinite alternate }` (line 173) and `.rz-entry.rz-is-current { animation: rz-foxfire 2.8s ease-in-out infinite alternate }` (line 271) — both top-level, infinite, outside the `@supports` block, and always present on Jordan's sandbox (the name is always there and `example.html` has one `rz-is-current` entry). `document.getAnimations()` is therefore never empty on Nightgarden on screen; every "nothing animates" oracle in this PBI is scoped to the sections — `[...document.querySelectorAll('.rz-section')].flatMap(s => s.getAnimations())` — never to the document
- All three first-party themes: `.rz-bullet, .rz-prose p { white-space: pre-line }`
- Contract §5.3 note: highlights may contain `\n`; themes should respect it (`white-space: pre-line`)
- Probes are Chromium-only (the only installed Playwright browser); the "unsupported browser" path is exercised by stripping the `@supports (animation-timeline: view())` block from the fetched theme text and injecting the remainder as a `<style>` in place of `#theme-stylesheet`
- The `rz-rise` probes open the résumé document as the **top-level** page via ZG-11's `openResumePage(browser, { theme: 'nightgarden', width: 1280, height: 800 })` (`/sandbox.html`), never through `#garden-frame`: the Garden iframe is a viewport-height internal scroller, so a page screenshot never contains its scrolled-out content
