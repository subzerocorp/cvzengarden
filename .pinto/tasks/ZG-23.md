## Why
`just verify` gates every round-1 PBI, but the S1 cold-load FOUC probe flakes on identical trees (60/60 pass, then 3/3 fail, then 2/3) because it samples `getComputedStyle` in a render-blocked sandbox — a state the browser never paints — so no persona-facing slice can be honestly verified and ZG-1 is stuck on "just verify exits 0".
## Covers
none (harness debt; keeps RZ-S1 / BAR-U1 "no FOUC on cold load" enforced with an oracle that observes painted frames)
## Scope in
- Replace the cold-load block of `s1Probes` in `frontend/scripts/probes.mjs` (the `browser.newPage()` + 36 × 20 ms `captureFrame` sampler, today lines ~620–632) with a paint-order oracle on a fresh page: `page.route('**/themes/*.css')` holds the theme sheet for `COLD_SHEET_DELAY_MS = 400` ms, the page is opened with `waitUntil: 'commit'`, and after the sandbox frame reaches `readyState === 'complete'` (plus one 200 ms settle) the probe reads, inside the sandbox frame (`page.frames().find(f => f.url().endsWith('sandbox.html'))`), `performance.getEntriesByType('paint')` and `performance.getEntriesByType('resource')` for the `#theme-stylesheet` href
- `ZG-23/cold-paint-order`: `first-contentful-paint.startTime >= responseEnd` of the theme sheet resource entry AND `>= COLD_SHEET_DELAY_MS`; the probe prints both numbers in the PASS/FAIL line
- `ZG-23/cold-paint-present`: exactly the `first-paint` and `first-contentful-paint` entries exist in the sandbox frame (a missing entry is `FAIL`, never a pass by absence), and after load `#theme-stylesheet.sheet.cssRules.length > 0` and `.rz-name` computed `font-family` is not `isUaDefaultSerif`
- `ZG-23/cold-sheet-blocking`: static lock on `dist/sandbox.html` — the single `id="theme-stylesheet"` link appears before `<body`, has `rel="stylesheet"`, and carries no `media`, `disabled`, or `onload` attribute
- The existing S1 swap-FOUC probe (`sampleDuring` with the 180 ms route delay) and its `isFoucSample` / `captureFrame` helpers stay byte-identical; `page.unroute` restores the route before later probes
- Retire the old cold-load PASS/FAIL strings; new lines follow `PASS  ZG-23/<slug>` / `FAIL  ZG-23/<slug> <reason>`
## Scope out
- Any change to `frontend/static/ports.js`, `generate.mjs`, the sandbox markup, chrome, or themes — the sandbox is already correct; only the oracle changes
- Retrying, re-running, or `SKIP`ping the cold-load probe — a retry that hides a real FOUC is rejected; a flaky oracle is replaced, not re-rolled
- Rasterised screenshots or PNG decoding (no decoder in the toolchain; cross-document canvas capture is not permitted)
- Sampling `getComputedStyle` during load as an oracle for paint (the defect being removed)
- The swap-FOUC probe, ZG-1's renderer diff, and any `just`/`justfile` change

## Notes
- Oracle rationale (verified 2026-08-23 with a throwaway Playwright run against `dist/`, sheet held 400 ms, two runs each): real sandbox → FP = FCP = 444 / 452 ms, sheet `responseEnd` = 413 / 412 ms; link at end of `<body>` → FCP = 32 ms; `media="print"` onload swap → FCP = 32 ms. Paint-timing entries are reported inside the same-origin sandbox iframe in headless Chromium, and the ~400 ms separation is what makes the oracle deterministic under machine load 2–4 while still failing on a genuine unstyled paint. Computed style in a render-blocked document is resolved ignoring pending sheets, which is why the old sampler could see "UA serif on blank canvas" for a frame that was never painted.
- If in execution `performance.getEntriesByType('paint')` is ever empty in the iframe, that is a FAIL of `cold-paint-present` to be investigated, not a reason to fall back to computed-style sampling.
