## Why
Priya wants "Publish / Copy link" and a sentence that says who can see her phone number and how to take it down; Marcus wants delete and his JSON back; Elena wants to know whether hosting exists (Priya, Marcus, Elena).
## Covers
B1 (chrome half), B2 — Priya, Marcus, Elena
## Scope in
- "Publish" button in the View section (enabled only after an Author Resume is loaded via ZG-5; disabled with hint on the sample) → `POST /api/resumes` with the current Resume and selected theme → shows `[data-publish-state="published"]` with: public URL + "Copy link" (`.copy-link` from ZG-8, variant), the edit link (`/?edit={id}:{key}` form the chrome understands), and the sentence "Save this edit link — it is the only way to change or delete your page. We cannot recover it."
- Edit link stored in `localStorage` (`resumezen.published`); opening `/?edit=…` loads the stored Resume (`GET /api/resumes/{id}` with key), sets the theme, and shows "Update" and "Delete" buttons; Delete asks once, then shows "Taken down"
- "Download my JSON" button (client-side from the loaded Resume; also works from the edit link)
- Trust copy next to Publish (`.publish-trust`) : "Only people with the link can see it — it is not listed or indexed. Kept until you delete it. Your JSON stays yours; download it any time. This is a free preview." plus a footer "Privacy" link opening the same panel with those answers and what the server stores (the JSON, the theme, timestamps; no analytics)
- Honest failure: API unreachable (static Netlify build) → `[data-publish-state="unavailable"]` "Publishing is not available on this build yet." (no spinner, no console error)
## Scope out
- Accounts/login, payments, vanity URLs, custom domains (Phase 5)
- Retention automation or a legal privacy policy document (the panel is plain-language, human to review wording)
- Publishing the sample résumé (Jordan is not a person)
- Server-side page listing or "recently published" gallery
