## Why
Priya wants "Publish / Copy link" and a sentence that says who can see her phone number and how to take it down; Marcus wants delete and his JSON back; Elena wants to know whether hosting exists (Priya, Marcus, Elena).
## Covers
B1 (chrome half), B2 — Priya, Marcus, Elena
## Scope in
- "Publish" button in the View section (enabled only after an Author Resume is loaded via ZG-5; disabled with hint on the sample) → `POST /api/resumes` with the current Resume and selected theme → shows `[data-publish-state="published"]` with: public URL + "Copy link" (`.copy-link` from ZG-8, variant), the edit link, and the sentence "Save this edit link — it is the only way to change or delete your page. We cannot recover it."
- After a successful publish the button reads "Update" and re-uses the same id via `PUT` — a second click never creates a second page
- Edit link form is `/#edit={id}:{key}` (fragment: never sent to the server, never in server logs or `Referer`); on load the chrome reads the fragment, stores it in `localStorage` (`resumezen.published`), and immediately `history.replaceState`s the hash away so the key does not linger in the address bar or history; the key travels only in the `Authorization` header. Opening the edit link loads the stored Resume (`GET /api/resumes/{id}` with key), sets the theme, and shows "Update" and "Delete"; Delete asks once (in-chrome confirmation with a cancel control), then shows "Taken down"
- "Download my JSON" button (client-side from the loaded Resume; also works from the edit link)
- Trust copy next to Publish (`.publish-trust`): "Only people with the link can see it — it is not listed or indexed. Kept until you delete it. Your JSON stays yours; download it any time. This is a free preview." plus a footer "Privacy" link opening the same panel with those answers and what the server stores (the JSON, the theme, timestamps; no analytics)
- Honest failure states, each a plain sentence with no spinner and no console error: API unreachable (static Netlify build) → `[data-publish-state="unavailable"]` "Publishing is not available on this build yet."; API answered 413 / 422 / 5xx → `[data-publish-state="error"]` with a sentence naming the cause (`too large`, the missing `name`, or "try again")
- Probe harness: `probes.mjs` starts the ZG-21 backend on `PROBE_PORT + 1` (`cargo run --manifest-path backend/Cargo.toml` with `RESUMEZEN_DB=:memory:`) for the publish probes; if it fails to start every publish probe prints `FAIL  ZG-22/<slug> prerequisite missing: backend` — `SKIPPED` is not a permitted outcome for this PBI's own probes
## Scope out
- Accounts/login, payments, vanity URLs, custom domains (Phase 5)
- Retention automation or a legal privacy policy document (the panel is plain-language, human to review wording)
- Publishing the sample résumé (Jordan is not a person)
- Server-side page listing or "recently published" gallery
- A `?edit=` query form (rejected: query strings reach server logs; the fragment form replaces it)
