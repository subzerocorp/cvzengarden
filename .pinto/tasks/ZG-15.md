## Why
Mika proofed her theme by hand-editing `example.html` because the flagship experience (flip a theme, print stays print) needs `npm` + an Elm build; a designer should drop her `.css` into the Garden and see it on the Skeleton, in print preview, and on paper (Mika, Devon).
## Covers
C5 — Mika, Devon
## Scope in
- "Try your own CSS" control in the switcher (`<input type="file" accept=".css,text/css">` + drop zone) that reads the file, creates a `blob:` URL, and swaps `#theme-stylesheet` through the existing dual-link path
- A pseudo card "Your file: ledger.css" (`#theme-option-local`) with the parsed `Name:`/`rz-target` from its header; selecting a first-party theme restores it; re-picking a file re-reads it
- Print preview and Print / Save as PDF work on the local sheet; `?theme=` is not pushed for the local file (URL shows no `theme` change)
- Reject non-CSS or files containing `<script` with `[data-theme-error]`
## Scope out
- Uploading or persisting the CSS anywhere (no Submission store this round; PR is the path — ZG-18)
- Live editing / a CSS editor in the chrome
- Linting the file inline (ZG-20's CLI is the lint; chrome may link to it later)
