## Why
Marcus's four-job résumé printed with page 1 seventy percent blank, Priya's Switchyard printout lost every bullet, and Nightgarden prints secondary text in pale lilac; the reference themes must teach break discipline on a senior résumé, not just on Jordan (Marcus, Priya, Mika, Elena).
## Covers
E1, E2 (Switchyard and Nightgarden print markers), E3 (pale print ink) — Marcus, Priya, Mika, Elena
## Scope in
- `themes/quarto.css`, `themes/switchyard.css`, `themes/nightgarden.css`: `.rz-section` computes `break-inside: auto` in print; keep `break-inside: avoid` on `.rz-entry` and `break-after: avoid` on `.rz-section-title` / `.rz-entry-header`; remove the unconditional `break-before: page` on `.rz-section--projects` in Switchyard. The rule lives in a different place per sheet: Quarto's `.rz-section { break-inside: avoid-page; page-break-inside: avoid }` is a **top-level** rule (lines 174–178, outside every `@media`; Quarto's print block has no `.rz-section` break rule at all), Switchyard's `.rz-section { break-inside: avoid }` (line 397) and `.rz-section--projects { break-before: page }` (line 402) are inside `@media print`, Nightgarden has no section-level avoid — so the Quarto fix edits or overrides the top-level rule, and no static "no theme has X in print" check in this PBI reads `extractMediaBlocks` output (it returns `@media` bodies only and would never see Quarto's rule)
- Switchyard `@media print .rz-bullet::before` gets a printed marker (ink-coloured bar with `print-color-adjust: exact`, or a text glyph)
- Nightgarden `@media print .rz-bullet::before` gets a printed marker too: today it is a `background: var(--rz-mint)` dot with no print override and no `print-color-adjust`, which prints pale or not at all — in print it becomes an ink bar/dot (`background-color` ≥ 4.5:1 against white, `print-color-adjust: exact`) or a text glyph
- Nightgarden `@media print .rz-entry-secondary`, `.rz-location`, `.rz-dates`, `.rz-meta` colour ≥ WCAG 4.5:1 against white
- Shared fixture (owner: this PBI) `frontend/fixtures/long-resume.json`: fictional senior engineer `Marcus Okafor-Lindqvist` — `basics.summary` of two paragraphs, 4 `work` entries with 4–6 highlights each (12–25 words per highlight), 2 `volunteer`, 2 `education`, 2 `awards`, 6 skill groups, 3 `projects` with 3 highlights each; the fixture is sized so that `ZG-11/fixture-trips-e1` holds at paper width — the ranges above are a guide, not a ceiling: lean long, and if `fixture-trips-e1` does not hold at 682 px under Quarto (4 × 6 highlights × 25 words is roughly 900–1000 px at 11 pt, near the 952 px threshold) exceed the highlight ranges (more highlights per entry, longer highlights) until it does; the cargo lock counts entries (4 / 3 / 2) and only a minimum of bullets, so highlights are the free dimension — the AC decides, not the counts; `frontend/fixtures/long-resume.html` = the exact `render_json` output for it (full document), locked by a cargo test `renderer/tests/fixtures.rs::long_resume_html_is_crate_output` (byte equality; regenerate with `RZ_UPDATE_FIXTURES=1 cargo test --test fixtures`) so the HTML cannot drift from the JSON
- Shared probe helper (owner: this PBI) `openResumePage(browser, { theme, width, height = 800, fixtureHtml })` in `probes.mjs`: opens `/sandbox.html` as the **top-level** page in a fresh `browser.newPage({ viewport: { width, height } })`, applies the theme with the existing `waitThemeReady(page, "themes/<theme>.css")`, and when `fixtureHtml` is given replaces `article.rz-resume` with the `<article class="rz-resume" …>…</article>` extracted from that HTML; returns the page. The helper uses the suite's existing `chromium.launch({ headless: true })` browser: Playwright's default headless args include `--hide-scrollbars`, and the helper never passes `ignoreDefaultArgs` or any scrollbar-showing flag, so a classic 15 px scrollbar cannot be the cause of an `article-width` FAIL — if that line appears it is a surviving UA margin or a print-block regression and is read as such. The Garden iframe (`.garden-frame { height: 100%; min-height: 100vh }`) is a viewport-height box that scrolls internally and lays the article out at the iframe's width, so no geometry, pixel or scroll probe measures inside it; ZG-12 reuses this helper
- Probe helpers in `probes.mjs`: `printableWidthPx(themeId)` and `printableHeightPx(themeId)` derived from each theme's `@page` size and margins — widths: Quarto 8.5in − 0.7in − 0.7in = 7.1in = 682 px; Switchyard 210mm − 16mm − 16mm = 178mm = 673 px; Nightgarden 8.5in − 0.5in − 0.5in = 7.5in = 720 px; heights: Quarto page 1: 11in − 0.48in − 0.6in = 9.92in = 952 px; Switchyard: 297mm − 14mm − 16mm = 267mm = 1009 px; Nightgarden: 11in − 0.36in − 0.28in = 10.36in = 995 px — and `paginate(page, printableHeight)`: greedy pagination in `emulateMedia({ media: 'print' })` over atomic blocks — the outermost elements whose print-emulated `break-inside` is `avoid`/`avoid-page`, otherwise the leaf block boxes (`.rz-header`, `.rz-entry`, `.rz-prose p`, `.rz-skill-group`, `.rz-section-title`) — the `.rz-header` is the first block placed on page 1, so the simulated page 1 has no more capacity than the real one — honouring `break-before: page`; an atomic block taller than the printable height starts a new simulated page and is placed alone on it (the next block begins the following page), so the pre-change run — where Quarto's top-level avoid makes the whole `#rz-experience` one atomic block — yields one deterministic page-1 ratio for every implementation; returns the block list per simulated page and the page-1 fill = (bottom edge of the last block on page 1 − top edge of the first block) ÷ printable height, so a theme's top padding never leaks into the ratio. This is a geometry oracle (Playwright cannot rasterise a PDF and the toolchain has no PNG decoder)
- Geometry probes (`fixture-trips-e1`, `page1-fill`, `entry-intact`) run on `openResumePage({ theme, width: printableWidthPx(theme), fixtureHtml: long-resume.html })` in print emulation, where every theme's print block sets `.rz-resume { width: auto; max-width: none; margin: 0; padding: 0 }` and `body { margin: 0 }`, so the article lays out at the paper's printable width; each geometry probe first asserts `article.rz-resume.getBoundingClientRect().width` is within 2 px of `printableWidthPx(theme)` (the width assumption is itself checked — a surviving UA margin fails it) and stops with `FAIL  ZG-11/<slug> article width <n>px, want <w>px` otherwise
- `U3_PRINT_PAGES` re-baselined to `{ nightgarden: 2, quarto: 2, switchyard: 2 }` for Jordan; a sibling constant `LONG_PRINT_PAGES` (exact per-theme page counts of `long-resume.html`, every value ≤ 3) committed with the fixture and asserted with `!==`

- [ ] Probe `ZG-11/article-width`: for each theme, `openResumePage({ theme, width: printableWidthPx(theme), fixtureHtml })` in print emulation reports `article.rz-resume.getBoundingClientRect().width` within 2 px of 682 (Quarto), 673 (Switchyard), 720 (Nightgarden); the pass line prints the measured width
- [ ] Probe `ZG-11/fixture-trips-e1`: on that page in print emulation, `#rz-experience` `getBoundingClientRect().height` > `printableHeightPx('quarto')` (952) under Quarto and > `printableHeightPx('switchyard')` (1009) under Switchyard — the fixture is proven to force a section-level break at paper width before any theme change is judged; the pass line prints both heights
- [ ] Probe `ZG-11/page1-fill`: `paginate` on that page reports page-1 fill ≥ 0.85 for Quarto and for Switchyard; the pass line prints the ratio (`PASS  ZG-11/page1-fill quarto 0.91`); the same probe run against the pre-change theme sheets (`git show <base>:themes/<theme>.css` injected in place of `#theme-stylesheet`) reports < 0.85 for both — that FAIL line is recorded in evidence (anti-vacuity)
- [ ] Probe `ZG-11/page-count`: `countPdfPages(printToPdf)` equals exactly `U3_PRINT_PAGES[id]` = `{ nightgarden: 2, quarto: 2, switchyard: 2 }` for `skeleton/example.html` (Quarto and Switchyard were 3) and exactly `LONG_PRINT_PAGES[id]` for `long-resume.html`, with every `LONG_PRINT_PAGES` value ≤ 3; the existing S3 / U3 probes assert the re-baselined `U3_PRINT_PAGES` with `!==` and are green
- [ ] Probe `ZG-11/no-forced-break`: on the top-level page in print emulation (`openResumePage` with `long-resume.html` at `printableWidthPx(theme)`), for each of the three themes every `.rz-section` computes `breakInside` `auto` (`getComputedStyle(section).breakInside`), and under Switchyard `.rz-section--projects` computes `breakBefore` other than `page` (`page-break-before: always` is an alias and computes to `page`); plus a static scan of the **whole** of `themes/switchyard.css` — top level and every `@media` body, not `extractMediaBlocks` output — finds no `break-before: page` / `page-break-before: always`. Anti-vacuity: the same probe run against the pre-change Quarto sheet (`git show <base>:themes/quarto.css` injected in place of `#theme-stylesheet`) FAILs because its top-level `.rz-section` rule (lines 174–178) computes `breakInside` `avoid` in Chromium — line 177's `page-break-inside: avoid` is an alias of `break-inside: avoid`, is declared after line 176's `avoid-page`, and wins the cascade; anything other than `auto` fails — that FAIL line (reading `avoid`) is recorded in evidence
- [ ] Probe `ZG-11/entry-intact`: in the `paginate` output for `long-resume.html` under Quarto and Switchyard at paper width, every `.rz-entry-header` and its `.rz-dates` fall on the same simulated page and no atomic block is taller than the printable height (stated approximation of the browser's break positions; same oracle as `page1-fill`)
- [ ] Probe `ZG-11/bullets-print`: in print emulation on the top-level page, for the first `.rz-bullet` of `long-resume.html` under each of the three themes, a marker exists — `getComputedStyle(el, '::before').content` is a quoted string other than `""` (a glyph; the CSSOM serialises with quotes, so Quarto's dash reads as `"– "`), **or** `content` is `""` (two quote characters — the CSSOM serialisation of an empty string, which is how every empty-content bar or dot reports) / `none` / `normal` and `getComputedStyle(el, '::before').width` and `.height` each parse to > 0 px (a pseudo-element is not an Element — there is no node to call `getBoundingClientRect()` on; the computed read returns the used box size, e.g. `8.79688px` / `2px` for a bar, and `auto` when `content: none` generates no box, which fails), **or** the `li`'s computed `list-style-type` is not `none` (never how a first-party theme passes: all three set `.rz-bullets { list-style: none }` — quarto 148, switchyard 115, nightgarden 199); and the marker is inked — a text glyph's `::before` computed `color` contrasts ≥ 4.5:1 against `#fff`, or an empty-content bar's/dot's `::before` has `width` > 0, `height` > 0, `background-color` contrasting ≥ 4.5:1, and `print-color-adjust: exact` (or `-webkit-print-color-adjust: exact`) computed on it; all three themes are held to the same assertion (Nightgarden's marker is in scope above; Quarto's `"– "` glyph inherits the print ink; a Switchyard or Nightgarden bar satisfies the marker-exists clause through its sized box, not through `content`; both clauses use the one read `getComputedStyle(el, '::before')`). Anti-vacuity, both failure modes seen once: against the pre-change sheets (`git show <base>:themes/<theme>.css` injected) Switchyard fails the marker-exists clause — its bar lives only in `@media screen` (lines 256–264), so in print emulation `content` is `none` and `width` is `auto` (E2 reproduced) — and Nightgarden fails the ink clause — its dot has a box but a mint `background-color` and no `print-color-adjust`; both FAIL lines are recorded in evidence
- [ ] Probe `ZG-11/print-ink`: in print emulation under Nightgarden, `.rz-entry-secondary`, `.rz-location`, `.rz-dates`, `.rz-meta` computed `color` each contrast ≥ 4.5:1 against `#fff` (helper `contrastRatio`)
