## Why
Every first-party theme leaks each visitor's IP to jsDelivr and loses its face when printing offline; a hosted résumé page must not phone a CDN (Marcus, Mika; BAR-L1).
## Covers
F6 — Marcus, Mika
## Scope in
- Vendor the exact woff2 files the three themes reference (EB Garamond, IBM Plex Sans, Syne, Outfit — all SIL OFL) under `themes/fonts/<family>/` with each family's `OFL.txt`
- `@font-face src` in `themes/*.css` becomes `local("…")`, then `url("fonts/…")` (relative to the CSS file); no `cdn.jsdelivr.net`
- `frontend/scripts/copy-dist.mjs` copies `themes/fonts/` to `dist/themes/fonts/`; `serve.mjs` already maps `.woff2` → `font/woff2`
- `themes/README.md`: first-party fonts are self-hosted; contributors may `@font-face` any https origin or self-host in their PR (the "allowlist" is "any https origin, self-hosted preferred") — this sentence is the C8 font-allowlist answer
- Probe `BAR-L1` (owner: this PBI — no such probe exists today): for each pair of first-party themes, `.rz-name` computed `color` or computed `font-family` differs; prints `BAR-L1 PASS|FAIL`
- Probe: request log during a full theme cycle and print has no third-party host
- Console-error convention for route-aborted probes (this PBI's `fallback`): Chromium logs `Failed to load resource: net::ERR_FAILED` as a console message of type `error` for every aborted request, so the probe forbids `pageerror` and every console error **except** those the abort itself causes (identified by `msg.location().url` or `msg.text()` containing `/themes/fonts/`) — the same `pageerror`-only stance ZG-4's `wasm-load-failure` takes
## Scope out
- Subsetting/optimising fonts beyond the latin files already used
- Font licensing for contributor themes (their responsibility; stated in ZG-18's CONTRIBUTING)
- Changing typefaces
- Re-baselining print page counts — a same-face swap must not reflow; if it does, the PBI returns to planning rather than editing the constants
