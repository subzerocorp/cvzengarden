## Scope in
- `backend/` Axum crate (`axum`, `tokio`, `tower-http` fs+cors, `libsql`, `serde`, `thiserror`); depends on `resumezen-renderer`; serves `frontend/dist` statically so one process runs the whole product locally (`just serve` uses it)
- Store: libSQL file `backend/data/resumezen.db` (gitignored) by default; `:memory:` in tests; `TURSO_DATABASE_URL` + `TURSO_AUTH_TOKEN` switch to Turso (env-driven, no code change). Table `resumes(id TEXT PK, edit_key_hash TEXT, theme_id TEXT, resume_json TEXT, created_at, updated_at)`
- `POST /api/resumes` body `{resume: <JSON Resume>, theme: "quarto"}` → `201 {id, public_url: "/r/{id}", edit_key}`; `id` = 10 chars base32 from 50 random bits; `edit_key` = 32 chars, stored as SHA-256; returned once
- `GET /r/{id}` → `200 text/html` server-rendered Skeleton with `<link rel="stylesheet" href="/themes/{theme}.css">` inserted after `<title>`; nothing else in the document (no chrome, no script); `Cache-Control: no-store`; `X-Robots-Tag: noindex` (link-only visibility)
- `PUT /api/resumes/{id}` (header `Authorization: Bearer <edit_key>`) replaces resume+theme; `DELETE` removes the row; `GET /api/resumes/{id}` with the key returns the stored JSON (export)
- Validation: body > 1 MB → 413; not JSON → 400 with the same plain message shape as ZG-5; unknown theme id → 422; `basics.name` missing → 422; wrong/absent key → 404 (do not reveal existence); deleted → `410` HTML page "This résumé was taken down."
- Layering: pure `domain` (ids, validation, render-with-theme calc) / `store` (libSQL actions) / `http` (handlers); errors via `thiserror` mapped to status codes in one place

## Acceptance criteria
- [ ] `cd backend && cargo test`: `publish_then_get_renders_theme` — POST `skeleton/resume.json` + `quarto` returns 201 with `id` matching `^[a-z2-7]{10}$` and a 32-char `edit_key`; `GET /r/{id}` is 200 `text/html` containing `<article class="rz-resume"`, `Jordan Hale`, `href="/themes/quarto.css"`, and no `<script`
- [ ] `get_json_requires_key`: `GET /api/resumes/{id}` without key → 404; with wrong key → 404; with the key → 200 body deep-equals the posted resume
- [ ] `put_replaces`: PUT with key and `{"basics":{"name":"Ada"}}` + `switchyard` → 200; `GET /r/{id}` shows `Ada`, `switchyard.css`, no `Jordan`
- [ ] `delete_then_gone`: DELETE with key → 204; `GET /r/{id}` → 410 with text `taken down`; DELETE again → 404
- [ ] `rejects_bad_input`: 1.1 MB body → 413; body `{` → 400 with message containing `line`; theme `banana` → 422 mentioning `theme`; missing name → 422 mentioning `name`; a `startDate: "２０２０"` (ZG-2) → 201, not 500
- [ ] `ids_unguessable`: 1,000 POSTs yield 1,000 distinct ids; `GET /r/aaaaaaaaaa` → 404
- [ ] `edit_key_not_stored_plain`: a direct SQL read of `edit_key_hash` never equals the returned key and has length 64 hex
- [ ] Static: `GET /` serves `frontend/dist/index.html`, `GET /themes/quarto.css` 200; `GET /skeleton/preview.css` 404
- [ ] `backend/README.md` documents env vars, `just serve`, and that `data/*.db` is never production; `.gitignore` covers `backend/data/`
- [ ] `cargo clippy --all-targets -- -D warnings -D clippy::pedantic` in `backend/` exits 0; `grep -rn anyhow backend/` empty; `just verify` green

## Notes
- Render side is decided: hosted pages render on the server from stored JSON with the same crate; paste renders in the browser via Wasm (ZG-4). No `/api/render` endpoint.
- `sha2` (or `ring`) for hashing and `rand`/`getrandom` for ids are outside the pre-approved list — human approval requested; std-only fallback is `std::hash` (not cryptographic) which the Generator rejects for the edit key.
- Retention: no automatic expiry this round; the human decides the retention wording (ZG-22 states "kept until you delete it; this is a preview").
