## Scope in
- `backend/` Axum crate (`axum`, `tokio`, `tower-http` fs only, `libsql`, `serde`, `thiserror`); depends on `resumezen-renderer`; serves `frontend/dist` statically so one process runs the whole product locally. No CORS layer: the API is same-origin only (the Garden is served by this process), which is what keeps ZG-22's "unavailable on the static Netlify build" story true
- Local run for personas: `just serve` builds the frontend and runs `cargo run --manifest-path backend/Cargo.toml` with `PORT` (default 4310) and `RESUMEZEN_DB` (default `backend/data/resumezen.db`); startup logs the listen address and DB path; when `frontend/dist/index.html` is missing the process exits 1 with a message naming `frontend/dist` and `npm run build`
- Store: libSQL file (gitignored) by default; `:memory:` in tests; `TURSO_DATABASE_URL` + `TURSO_AUTH_TOKEN` switch to Turso (env-driven, no code change). Table `resumes(id TEXT PK, edit_key_hash TEXT, theme_id TEXT, resume_json TEXT, created_at, updated_at, deleted_at NULL)` — `deleted_at` is nullable and NULL until DELETE; `edit_key_hash` and `resume_json` are NULL only on a tombstone; `resume_json` is stored verbatim (contract §1.8: unknown keys and `meta` round-trip)
- `POST /api/resumes` body `{resume: <JSON Resume>, theme: "quarto"}` → `201 {id, public_url: "/r/{id}", edit_key}`; `id` = 10 chars base32 (`[a-z2-7]`) from 50 random bits; `edit_key` = 32 chars from a CSPRNG, stored as SHA-256; returned once
- `GET /r/{id}` → `200 text/html` server-rendered Skeleton with `<link rel="stylesheet" href="/themes/{theme}.css">` inserted after `<title>`; nothing else in the document (no chrome, no script, no other `<link>`); headers `Cache-Control: no-store` and `X-Robots-Tag: noindex` on every `/r/{id}` response (200 and 410)
- `PUT /api/resumes/{id}` (header `Authorization: Bearer <edit_key>`) replaces resume+theme with the same validation as POST; `GET /api/resumes/{id}` with the key returns the stored JSON (export). `DELETE` erases the résumé and keeps a tombstone: it sets `resume_json` and `edit_key_hash` to NULL and `deleted_at` to now (the table gains a nullable `deleted_at`), leaving the `id` row in place so `GET /r/{id}` answers 410 forever and an id is never reissued; a direct SQL read of the row after DELETE finds no résumé bytes and no key hash. The edit key is accepted only in the `Authorization` header — never as a query parameter
- Validation (POST and PUT, in this order, first failure wins): body > 1 MiB (1 048 576 bytes) → 413 `too-large` — the limit applies to the bytes actually received (the decoded body), not to `Content-Length`, so a chunked request or one without a `Content-Length` cannot bypass it; body not JSON → 400 `invalid-json` (message carries `line N column M`); `theme` absent or not a catalog id → 422 `unknown-theme` (the message names `theme`); shape check, a pure `domain` calculation mirroring ZG-5's `not-a-resume` class — `resume` not an object, `basics` present but not an object, or any known section key (`work`, `volunteer`, `education`, `awards`, `certificates`, `publications`, `skills`, `languages`, `interests`, `references`, `projects`) present but not an array → 422 `not-a-resume` with the message naming the offending key; `basics.name` missing or blank → 422 `missing-name`; finally `resumezen_renderer::render_json` on the `resume` value — `Err` (any deeper shape error serde rejects, e.g. a highlight that is not a string) → 422 `not-a-resume` with a plain sentence (never 500, never a panic). A row is written only after `render_json` succeeded on the exact bytes being stored, so `GET /r/{id}` renders JSON that is known to render
- Error body (owner: this PBI; ZG-22's `api-errors` stubs use this shape): every non-2xx response under `/api/` is `Content-Type: application/json` with exactly `{"error": "<code>", "message": "<plain sentence>"}` — codes `too-large`, `invalid-json`, `unknown-theme`, `not-a-resume`, `missing-name`, `not-found`, `method-not-allowed`; this includes the router's fallbacks — an unmatched path under `/api/` is 404 `not-found` and a wrong method on a matched `/api/` route is 405 `method-not-allowed`, both in the same JSON shape (never Axum's empty `text/plain` default); `message` is the humane sentence (for `missing-name` it contains `name`; for `not-a-resume` the key; for `invalid-json` `line N column M`) and never contains a Rust/serde token (`expected`, `EOF`, `invalid type`, `serde`, `Err(`, `panicked` — ZG-5's ban list); a client shows `message` and may fall back to `error`. `/r/{id}` responses (404, 410) stay `text/html`
- wrong/absent key → 404 `not-found` (do not reveal existence); ids not matching `^[a-z2-7]{10}$` → 404 before any DB read; deleted → `410` HTML page "This résumé was taken down."
- Layering: pure `domain` (ids, validation incl. the shape check, render-with-theme calc) / `store` (libSQL actions) / `http` (handlers); errors via `thiserror` mapped to status code + `{error, message}` in one place

## Acceptance criteria
- [ ] `cd backend && cargo test`: `publish_then_get_renders_theme` — POST `skeleton/resume.json` + `quarto` returns 201 with `id` matching `^[a-z2-7]{10}$` and a 32-char `edit_key`; `GET /r/{id}` is 200 `text/html` containing `<article class="rz-resume"`, `Jordan Hale`, `href="/themes/quarto.css"`, and no `<script`
- [ ] `public_page_headers_and_purity`: `GET /r/{id}` carries `Cache-Control: no-store` and `X-Robots-Tag: noindex`; the body contains exactly one `<link` (the theme), no `theme-switcher`, no `garden`, no `<iframe`; after DELETE the 410 response carries the same two headers
- [ ] `get_json_requires_key`: `GET /api/resumes/{id}` without key → 404; with wrong key → 404; with the key → 200 body deep-equals the posted resume
- [ ] `unknown_keys_round_trip`: POST a résumé containing `meta.x-custom: "kept"` and a top-level `"x-vendor": {"a": 1}`; `GET /api/resumes/{id}` with the key returns both verbatim; `GET /r/{id}` still renders
- [ ] `put_replaces`: PUT with key and `{"basics":{"name":"Ada"}}` + `switchyard` → 200; `GET /r/{id}` shows `Ada`, `switchyard.css`, no `Jordan`
- [ ] `put_and_delete_require_key`: PUT and DELETE with absent key → 404, with wrong key → 404, and `GET /r/{id}` still shows `Jordan Hale` and `quarto.css` afterwards (row unchanged); PUT on a deleted id with the old key → 404
- [ ] `put_validates_like_post`: PUT with body `{` → 400 `invalid-json` containing `line`; theme `banana` → 422 `unknown-theme`; missing name → 422 `missing-name`; `{"basics":{"name":"E"},"work":"nope"}` → 422 `not-a-resume` with `message` containing `work`; 1 MiB + 1 byte → 413 `too-large` — each leaves `GET /r/{id}` unchanged
- [ ] `delete_then_gone`: DELETE with key → 204; a direct SQL read of the row by id after the 204 finds the row still present with `resume_json IS NULL`, `edit_key_hash IS NULL` and `deleted_at IS NOT NULL` (tombstone: no résumé bytes, no key hash, id reserved); `GET /r/{id}` → 410 with text `taken down`; DELETE again → 404; `GET /api/resumes/{id}` with the old key → 404
- [ ] `rejects_bad_input`: 1 MiB + 1 byte body → 413 and exactly 1 MiB (padding `basics.summary`) → 201; body `{` → 400 with message containing `line`; theme `banana` → 422 `unknown-theme` mentioning `theme`; missing name → 422 `missing-name` mentioning `name`; body with `resume` but no `theme` key → 422 `unknown-theme` mentioning `theme`; the 1 MiB + 1 byte body sent with `Transfer-Encoding: chunked` and no `Content-Length` → 413 `too-large` (the limit counts bytes received); a `startDate: "２０２０"` (ZG-2) → 201, not 500
- [ ] `wrong_shape_is_422_never_500`: `{"basics":{"name":"E"},"work":"nope"}` → 422 `{"error":"not-a-resume"}` with `message` containing `work`; `{"basics":"E"}` → 422 `not-a-resume` naming `basics`; `{"basics":{"name":"E"},"work":[{"highlights":"x"}]}` (passes the key check, fails in `render_json`) → 422 `not-a-resume`; `{"basics":{"name":"E"},"education":[{"score":3.7}]}` (ZG-3 wild input) → 201; none of these returns 500, and no row is written for the 422s (store call count for inserts is 0)
- [ ] `error_body_shape`: for each of the 400, 413, 422 cases above, for `GET /api/resumes/abc` (404), for `GET /api/nope` (unmatched path → 404 `not-found`) and for `PATCH /api/resumes/{id}` (wrong method on a matched route → 405 `method-not-allowed`), the response has `Content-Type: application/json`, the body parses to an object with exactly the keys `error` and `message`, `error` is one of `too-large` `invalid-json` `unknown-theme` `not-a-resume` `missing-name` `not-found` `method-not-allowed`, `message` is non-empty, and `message` contains none of `expected`, `EOF`, `invalid type`, `serde`, `Err(`, `panicked`
- [ ] `malformed_ids_are_404`: `GET /r/AAAAAAAAAA`, `/r/abc`, `/r/aaaaaaaaaa1`, `/r/aaaaaaaaaa%2F..%2Fx`, `/api/resumes/abc` (with any key) → 404, never 500, and no DB query is issued for them (store call count 0 via the test store wrapper)
- [ ] `ids_and_keys_unguessable`: 1 000 POSTs yield 1 000 distinct ids and 1 000 distinct `edit_key`s; `GET /r/aaaaaaaaaa` → 404
- [ ] `edit_key_not_stored_plain`: a direct SQL read of `edit_key_hash` never equals the returned key and has length 64 hex
- [ ] `key_only_in_header`: `GET /api/resumes/{id}?key=<edit_key>` and `?edit_key=…` → 404 (query-string keys are ignored)
- [ ] `no_cors`: `POST /api/resumes` with header `Origin: https://example.com` succeeds like any other request but the response carries no `Access-Control-Allow-Origin`; `OPTIONS /api/resumes` with `Origin` + `Access-Control-Request-Method: POST` returns no `Access-Control-Allow-*` header
- [ ] Static: `GET /` serves `frontend/dist/index.html`, `GET /themes/quarto.css` 200; `GET /skeleton/preview.css` 404
- [ ] `missing_dist_is_a_clear_error`: starting the binary with `frontend/dist` absent exits non-zero and stderr contains `frontend/dist` and `npm run build`

## Notes
- Render side is decided: hosted pages render on the server from stored JSON with the same crate; paste renders in the browser via Wasm (ZG-4). No `/api/render` endpoint.
- `sha2` (or `ring`) for hashing and `rand`/`getrandom` for ids are outside the pre-approved list — human approval requested; std-only fallback is `std::hash` (not cryptographic) which the Generator rejects for the edit key.
- Retention: no automatic expiry this round; the human decides the retention wording (ZG-22 states "kept until you delete it; this is a preview").
